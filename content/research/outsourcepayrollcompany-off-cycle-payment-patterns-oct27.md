Published October 27, 2026.

This audit classifies off-cycle payment requests by the problem that created them and the point at which they entered the payroll calendar. It is a workflow review, not a benchmark of payroll team quality.

## Research question and decision use

The question is which causes generate off-cycle runs and how often the request arrives after the regular payroll cutoff. Leaders can use the pattern to fix timekeeping deadlines, approval routing, and first-pay setup. The audit should not be used to compare offices without accounting for volume, shift mix, and local pay rules.

## Population and eligibility

Include every off-cycle request opened in the window that names an employee and a pay period, whether paid or denied. Record the source system, the request date, the pay date, and the status. Exclude test transactions and duplicates that were merged into an existing request, and keep the exclusion count.

## Cause codes and evidence

Use a fixed code set: missed regular payment, termination or final pay, retroactive adjustment, bonus or incentive, correction, and approved exception. Attach the source register line, approval, and correction record to each case. A request without evidence stays in an unclassified group rather than being forced into the nearest code.

## Timing and approval measures

Measure the interval from the triggering event to the request, from the request to approval, and from approval to payment. Record whether the request arrived before or after the published cutoff. Capture the approver role and whether a backup was used, but do not score individuals on response time.

## Analysis plan

Report request counts by cause, department, and cutoff position, with the total payroll population as the denominator where appropriate. Show the median and upper quartile of each interval. Compare the current period with a prior period using the same codes, and disclose any change in the code set before presenting a trend.

## Exception and sensitivity review

Separate denied requests from paid requests and note the reason. Test whether the conclusion changes when same-day requests are excluded or when one large department is removed. Inspect a small set of narratives behind unusual clusters before assigning a cause; a new timekeeping rule can look like an approval problem.

## Privacy and limitations

Aggregate at the level needed for the decision and avoid employee-level detail in the report. The audit observes recorded requests and cannot prove that a different cutoff would have prevented the underlying event. Missing off-system requests, reclassified causes, and policy changes limit comparison across periods.

## Replication package

Retain the request export, codebook, evidence links, approval log, cutoff calendar, calculations, and the report table. A later reviewer should be able to rebuild the counts and identify every case that was excluded. Document any code change before the next cycle.
